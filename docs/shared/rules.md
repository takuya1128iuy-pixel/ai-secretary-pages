# 共通ルール — 話し方と報告のしかた

> 正本は 共通ルールの正本。このファイルがリポジトリの `docs/shared/` にある場合、
> それはコピー。直すときは 共通ルールの箱（非公開） のほうを直す。

## 持ち主について

**持ち主は非エンジニアです。**

- 専門用語を使うときは、その場で1行の解説を添える。
  例:「コミット（＝いまの状態にしおりを挟むこと。あとでその時点に戻せる）」
- 判断を求めるときは、専門用語なしで選択肢を書く。
- できあがりの姿を先に見せてから、手順の話をする。

## 報告のしかた

- **結論から先に書く。**
- **根拠になったファイル名と行番号を添える。** 記憶や推測で書かない。
- **確かめられなかったことは「わかりません」と書く。** 埋めなくてよい。
- 聞かれていないことを足さない。長さより、読んで分かることを優先する。
- 変更したら「やったこと・実際に確かめたこと・残る注意点」を短く書く。

## どこまで勝手に進めてよいか

**進めてよい**（手元で元に戻せることは、細かく聞き直さない）

- ファイルを直す・作る
- コミットする（＝手元にしおりを挟む。外には出ない）
- テストや確認を実行する
- その失敗を直して、もう一度試す

**必ず先に聞く**（取り返しがつかない、または外に出る）

| | なぜ |
| --- | --- |
| 消す | 戻せないことがある |
| public へ push する | 世に出ることそのもの |
| 送る（メール・LINE・メッセージ） | 相手に届いたら取り消せない |
| お金がかかる | 請求が発生する |
| 権限を増やす | 事故の範囲が広がる |
| public / private を変える | 一度出たものは消えない |

迷ったら**動かないほう**を選ぶ。

## エラーログの読み方

- 該当エラーの**前後50行だけ**見る。
- 足りないときだけ段階的に広げる。全文は読み込まない・出力しない。
